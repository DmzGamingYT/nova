Dépannage

Un souci ? Il est presque certainement dans cette liste — et la solution tient en une commande ou deux.

Checksum SHA-256 Gatekeeper (macOS) SmartScreen (Windows) Micro muet
1

Le checksum SHA-256 ne correspond pas

Ne lance pas le DMG ni l'exe. La cause la plus fréquente est bénigne : un téléchargement incomplet — un proxy ou un Wi-Fi captif peut tronquer les gros fichiers sans prévenir. Retélécharge d'abord, remets SHA256SUMS.txt (téléchargeable sur la page de la release) à côté du fichier, puis revérifie :

shasum -a 256 -c SHA256SUMS.txt   # macOS · sha256sum -c sur Linux
  • : OK → c'était un téléchargement incomplet, tout va bien ;
  • encore différent → compare avec le bloc « Checksums SHA-256 » des notes de la release (et sur le site : la puce SHA-256 de la page Installation est cliquable pour copier l'empreinte complète), puis ouvre une Issue avec la version, ton OS et le hash obtenu.

Chaque release publie les checksums du DMG, de l'installeur Windows et du ZIP de mise à jour — le même fichier SHA256SUMS.txt couvre tout, quelle que soit ta plateforme.

2

macOS refuse d'ouvrir Nova (Gatekeeper)

C'est le prix du build non signé — macOS protège par défaut. Trois leviers, du plus simple au plus direct :

  1. Clic droit → Ouvrir sur Nova.app (un vrai clic droit, pas un double-clic), puis « Ouvrir » dans le dialogue — suffit dans la plupart des cas ;
  2. Réglages Système → Confidentialité et sécurité : descendre au bloc « Nova a été bloqué… » → Ouvrir quand même ;
  3. si le message dit « Nova est endommagé » (fréquent pour les builds ad-hoc sur les macOS récents), retire l'attribut de quarantaine posé au téléchargement :
xattr -dr com.apple.quarantine /Applications/Nova.app

La commande ne contourne rien : elle dit juste à Gatekeeper que tu as choisi cette app toi-même. Quand l'app sera signée et notariée (secrets Apple en CI), tout ce paragraphe disparaîtra.

3

Windows signale Nova (SmartScreen)

Même logique que macOS : l'installeur n'étant pas signé, Microsoft Defender SmartScreen affiche « Windows a protégé votre ordinateur ». Pour lancer quand même :

  1. dans le dialogue SmartScreen, clique Informations complémentaires ;
  2. puis Exécuter quand même — l'installeur reprend son cours normal ;
  3. si ton antivirus met l'installeur en quarantaine, restaure-le et vérifie d'abord son checksum (point 1) : si le hash correspond à celui de la release, le fichier est intact — l'alerte vient uniquement de l'absence de signature.

L'app n'a pas besoin des droits administrateur : elle s'installe dans ton profil utilisateur et son serveur interne n'écoute que sur 127.0.0.1, jamais sur le réseau.

4

Le micro ne fonctionne pas

  1. Permission macOS : Réglages Système → Confidentialité et sécurité → Micro → active Nova. Si elle n'apparaît pas dans la liste, lance l'app et tente un tour de micro : macOS l'inscrit alors automatiquement.
  2. Permission refusée avant ? macOS ne repose jamais la question — remets-la à zéro, puis relance Nova et accepte la demande :
tccutil reset Microphone app.nova.assistant
  1. Lancé via npm start en dev ? C'est le terminal (ou Electron) qui détient la permission, pas « Nova » — cherche le nom de ton terminal dans la liste du point 1.
  2. Démo web dans le navigateur ? Le micro dépend des permissions du site : icône cadenas ou micro dans la barre d'adresse → Autoriser, puis recharge la page.

Toujours bloqué ? Ouvre une Issue — précise la version (menu de l'app), ton OS et ce que tu observes.

Astuce : la page Nouveautés liste toutes les versions avec leurs notes ; le script de release montre exactement d'où viennent les checksums.
